# PBMS 网页录入与恢复

## 登录与记录恢复

复用当前PBMS标签页，读取实时状态再操作。会话过期时请用户登录。不要重放带 code、token、session_state 的登录回调URL；回调出错时返回正常首页检查会话。

区分三个持久状态：

|状态|可验证证据|恢复方式|
|---|---|---|
|仅在费用窗口编辑|还未出现在主表|可能未保存，重新登录后检查，不假定保留|
|有效草稿|Drafts中的ID、Active、更新时间及恢复后的内容|编辑当前有效草稿|
|已保存BR|BR编号、New或后续状态|按BR恢复，不另建草稿|

恢复后核对人员、日期、用途、纸质材料、职级、费用条数与合计。报告“最新已保存版本”与“最新讨论但未应用的修改”的差异，不把聊天确认当作已写入。

## 关联出差审批

教职工入口：Travel Reimburse → New Reimbursement → Associate DingTalk Travel Orders。

有清晰钉钉编号时，可直接输入 DingTalk Travel Application No. 并 Confirm；也可上传审批单让系统识别。核对带出的编号和日期。邮件审批等其他形式按当前系统入口及用户说明处理，不编造钉钉编号。No Business Trip Application Form只用于实际适用的无审批情形，不用来绕过已有审批。

恢复旧草稿时，可能需先经过New Reimbursement及审批关联入口进入编辑页。进入表单不代表创建了新持久记录；随后检查恢复的内容或用Drafts打开有效记录，不点Save Draft新建重复项。

## 人员字段

- Personnel Level是OCR前置条件。职级档位不可仅由姓名或通用Faculty审批类型推断。
- Traveler的校内选择器与Payee分开。辅助功能树可能显示空文本框，但可见标签已有姓名；必要时查看截图或DOM标签，不因单个空input判定未选。
- Payee → Select → Users：核对姓名与Staff No.。双击可能追加到Selected Payee，不自动替换默认登录人；确认列表只保留用户指定收款人后Confirm。
- Expenditure owner需从候选列表选定正确人员ID，不能只键入姓名。相同姓名可能对应教职工、学生或其他账户。
- 收款账户使用系统已有记录，避免将完整银行账号抄入交接报告或公开skill。

## OCR首步

先Expense Type，再Expenditure owner，再Fund。费用归属可默认登录人，每次打开新窗口都复核。

Fund选择器先选适用境内/境外科目，再选用户指定项目及预算明细。项目有直接费用、间接费用或绩效等多行时，不把同项目号当成同一预算；选择理由不明确时询问。

本流程用户确认过：城市间交通预算树仅提供Ground Transportation时，机票也可用对应的Domestic/Offshore选项。视为PBMS操作经验，核对当前入口与组织财务口径，不推为所有机构的会计规则。

候选列表异步加载：等加载完成后选择，再核对表单回填。不要在查询刷新中点击旧行；若点击Confirm提示未选预算，重新读取结果并选择目标，不重复盲点。

上传时分别核对左右文件名、文件数量和完成状态，完成后才Next。多文件识别后必须逐行对应原凭证，不依据返回顺序盲填。

## 字段及计算的有效提交

页面至少存在两类控件：OCR步骤中的选择器，以及编辑窗口中的EasyUI控件。直接填显示框可能没有提交到组件模型。

- 输入日期或金额后移出焦点/按控件要求确认；若无效，使用日历或普通键盘输入，不直接写内部状态。
- 日历按可见年月选择；定位日期时避开主表同名序号。只读日期框需点日历图标或单元格，不能强行赋值。
- 修改金额不一定触发人民币重算。核对显示的人民币值，必要时重新选定当前币种触发计算；异步刷新后再做下一次依赖操作。
- 原币金额、汇率、人民币结果三者必须一致。金额单位、小数点和千位分隔不能由OCR默认解释。
- 日期应依据该字段的业务含义：交通通常使用实际乘车/乘机日，不使用后来开票日；费用发生日、付款日、归属日需分清。
- 城市按地址判断，岛屿或地区名不等于具体城市。查询没结果可Reset，等列表稳定后搜索国家或城市；切换搜索词时避免叠加旧筛选。
- 原生编辑窗口改变Expense Type可能清空预算和城市，必须重新核对全部关联字段。

遇到工具报错，先读状态确认动作是否已生效，再决定重试；不要让一次成功但返回报错的操作生成重复明细。

## 保存与提交

1. 费用第3步核对明细及附件，Save后检查主表。
2. 主表Save Draft后检查成功提示；重要阶段记录当前有效ID。它可能更新同一ID，也可能生成新ID并停用旧项，以实时状态为准。
3. 全量核对后，按用户授权点击主表Save。若出现超限/超期提示，按review.md处理；普通“是否保存”确认属于已授权保存的后续步骤。
4. 成功生成BR后，详情页核对汇总、人员、经费与附件。Common中未见国内发票时检查Domestic Invoice；钉钉编号关联可能自动生成审批附件。
5. Batch Upload可补充通知，选择正确附件类型，完成后关闭上传窗口刷新清单并复验。附件可见及有下载链接不等于已逐个下载检查；报告实际核对范围。
6. 最终Submit必须有明确用户授权。提交窗口如需要新的实质信息，先确认；成功以工作流时间和下一节点为证据。不要点击后续审批动作。
